# FreeCAD BIM Meeting Notes

## Overview

The meeting focused on improving coordination around FreeCAD BIM development, establishing a lightweight roadmap, improving PR review and maintenance, and discussing several technical and organizational topics.

Participants agreed that regular meetings could help provide a central place for BIM contributors, developers, testers, documentation contributors, and users to coordinate work and discuss priorities.

## Meeting organization

There was general agreement that future meetings should have a lightweight agenda rather than being completely informal.

The proposed format is a shared, editable document with a few recurring topics, while still allowing new topics to be added freely.

Possible recurring agenda items include:

* Open PRs requiring review or testing
* Bugs, regressions, and feature requests
* Development priorities and roadmap topics
* Current development work
* Larger architectural or workflow proposals

A shared FreeCAD Cloud agenda document was created during the meeting and confirmed to be accessible.

## BIM roadmap

The group discussed whether BIM should have a strict roadmap or a more flexible set of priorities.

The consensus was that the roadmap should be driven by what contributors are realistically able and interested to work on rather than defining a large plan without people available to implement it.

As a starting point, contributors were encouraged to prepare their own short roadmap or list covering:

* What they are currently working on
* What they would like to work on
* What they consider important for BIM
* Important work that they cannot personally implement

These individual views can then be combined to identify shared priorities, overlapping initiatives, and areas where contributors can collaborate.

The group also discussed reviewing existing BIM/Draft issues and feature requests and assigning clearer priorities. This would help both existing and new contributors identify valuable work.

## Development priorities and typing

João described ongoing work to introduce stronger Python typing for Draft and BIM.

The goal is to improve:

* Code completion
* Developer documentation
* Static checking
* Detection of invalid API usage and other mistakes

The work uses standard Python type-hinting mechanisms and existing type-checking tools rather than a FreeCAD-specific solution.

There was also discussion about modernizing docstrings alongside type hints. With type information available directly in function signatures, documentation could focus more on explaining behavior and intent instead of duplicating parameter type information.

Marcus proposed opening an issue covering type hints and related documentation improvements.

## PR reviews and BIM maintenance

A major topic was the current BIM maintainer/reviewer workload.

Roy explained that reviewing BIM PRs alone is difficult, particularly for larger or technically complex changes involving Python or C++. The group discussed moving toward shared responsibility rather than relying on one person.

Potential contributions to the review process include:

* Code review
* Functional testing
* Checking whether a proposal fits BIM workflows and architecture
* Triaging issues and PRs
* Providing the final maintainer approval

João offered to become more active in reviewing BIM PRs.

The group also suggested using these meetings to review difficult PRs collectively when useful.

For large changes, there was agreement that discussing the architecture and rationale before implementation could make later review significantly easier.

Smaller or staged PRs were also encouraged where practical.

## Upcoming release / open PRs

Contributors were encouraged to review the BIM and Draft PR backlog, especially work intended for the upcoming release.

PR authors should move relevant PRs out of draft status when they are ready and clearly indicate where testing or review is needed.

Testing was highlighted as an area where non-maintainer contributors can provide substantial help.

## IFC / IFCx involvement

The group discussed whether FreeCAD should become more involved with the development of the next generation of IFC / IFCx standards.

Rather than FreeCAD directly providing significant development manpower, one possible approach would be to support existing open-source IFC experts already involved in the process, including people connected with IfcOpenShell.

The topic needs broader discussion, potentially at an FPA meeting. Marcus indicated that he could bring the subject there for further discussion.

## Arch → BIM naming cleanup

The group discussed completing the transition from the older `Arch` naming toward the current `BIM` module naming.

There was broad support for the cleanup, but backwards compatibility for existing add-ons and external code was considered important.

The suggested approach is:

* Document the overall migration plan in an issue
* Perform the migration incrementally where useful
* Maintain backwards compatibility for a significant transition period, potentially around one to two years
* Consider providing scripts or tooling to help add-on developers migrate
* Account for open PRs that may still use the old naming

João offered to help with the implementation/migration PR, while Marcus would document the broader rationale and migration plan.
